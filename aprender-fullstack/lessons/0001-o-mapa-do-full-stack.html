O mapa do full stack

Cliente, servidor e banco de dados: as três peças de todo sistema web, vistas dentro do seu próprio projeto.

Sua vitória de hoje: abrir o seu projeto cronograma-ia e apontar o que é frontend, o que é backend e o que é banco de dados. Depois, ver com os próprios olhos uma requisição acontecendo no navegador.

Por que começar por aqui

A IA já escreve código nas três camadas de um sistema. O que as empresas cobram de um júnior hoje é saber revisar esse código e dizer onde está o problema.1 Não dá para revisar o que você não consegue localizar. Por isso a primeira habilidade é ter o mapa.

As três camadas

Pense num restaurante.

No restauranteNo sistemaO que fazOnde roda
SalãoFrontendO que a pessoa vê e toca: telas, botões, formulários. Feito com HTML, CSS e JavaScript.No navegador de quem usa
CozinhaBackendAs regras: quem pode entrar, como calcular um orçamento, o que salvar.Num servidor
DespensaBanco de dadosGuarda os dados de forma organizada e permanente: usuários, orçamentos, projetos.Num servidor de banco

Um detalhe que cai em entrevista: tudo o que chega ao salão está na mesa do cliente. Ele pode olhar, mexer e trocar. Por isso regras importantes, como conferir uma senha, ficam na cozinha (backend), nunca só no salão.

Desenvolvedor full stack é quem sabe trabalhar nas três camadas.

A viagem de um clique

  1. Você digita um endereço ou clica num botão. O navegador é o cliente.2
  2. O DNS descobre onde fica o servidor. Ele funciona como a lista telefônica da internet: troca o nome do site pelo endereço numérico (IP) do servidor.2
  3. O navegador envia uma requisição HTTP ao servidor, dizendo o que quer.
  4. O servidor executa o backend. Se precisar, consulta o banco de dados.
  5. A resposta volta, com a página (HTML, CSS, JavaScript) ou só dados. O navegador monta tudo na tela.

E onde entra a IA?

No seu próprio projeto. O arquivo cronograma_app.html (frontend) chama a IA assim:

const resp = await fetch('https://api.anthropic.com/v1/messages', { ... })

fetch é o jeito do JavaScript fazer uma requisição. Ou seja, para o seu app a IA é "mais um servidor": recebe um pedido e devolve uma resposta. É a mesma viagem do diagrama.

E quando você usa um assistente de IA para programar, ele escreve código para qualquer uma das três camadas. O seu valor como dev está em saber qual camada pedir e onde procurar quando algo quebra.

Pratique: classifique o seu projeto

Para cada item do cronograma-ia, escolha a camada. Responda de memória, sem rolar a página para cima. Esforçar-se para lembrar é o que fixa o conteúdo.

cronograma_app.html

É uma página HTML com JavaScript. Ela é baixada e roda no navegador de quem usa, ou seja, é o salão.

backend/app/main.py

É o arquivo que liga o servidor do seu sistema (escrito em Python com FastAPI). Ele roda no servidor: é a cozinha.

A lista de orçamentos salvos dos seus clientes

Dados que precisam continuar existindo amanhã ficam guardados no banco. No seu projeto, é um PostgreSQL: a despensa.

backend/app/routers/orcamento.py

Fica dentro da pasta backend/ e define o que o servidor faz quando recebe pedidos sobre orçamentos. É uma receita da cozinha.

O botão que você toca para gerar um cronograma

Tudo o que a pessoa vê e toca é frontend. O botão só dispara a requisição; quem processa é outro lugar.

Pratique: entenda a viagem

1. Você digitou o endereço de um site. Quem descobre o número (IP) do servidor?

O DNS é a lista telefônica da internet: transforma o nome do site no endereço numérico do servidor. Só depois disso a requisição pode sair.

2. Onde roda o JavaScript que está dentro do seu cronograma_app.html?

O arquivo HTML é baixado pelo navegador, e o JavaScript dele roda ali, na máquina de quem usa. A Anthropic só recebe a requisição que esse código envia.

3. Por que conferir a senha de um usuário só no frontend é um erro grave?

O código do frontend está na máquina do usuário, que pode ler e modificar esse código. Regras de segurança precisam rodar no backend, onde o usuário não consegue mexer.

4. A IA gerou um código, e a lista de orçamentos aparece vazia na tela. Qual é o primeiro passo de um bom júnior?

Primeiro localize. Se a resposta do servidor trouxe os orçamentos e a tela continua vazia, o erro está no frontend. Se a resposta veio vazia, o erro está no backend ou no banco. A tarefa abaixo mostra onde ver isso.

Tarefa no mundo real (10 minutos)
